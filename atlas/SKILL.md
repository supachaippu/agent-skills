# Atlas: Scoped Session Resume & Task Continuation

เมื่อผู้ใช้ส่งโฟลเดอร์, ระบุพาธโครงการเพื่อรับช่วงงานต่อ, หรือพิมพ์ `/atlas`, "resume", "เริ่มต่อ", "ต่อจากเดิม":
ให้ปฏิบัติตามกฎเหล็กทั้ง 6 ข้อนี้อย่างเคร่งครัด:

---

## 1. ค้นหาและอ่านไฟล์ Handoff ในโฟลเดอร์ที่ระบุเท่านั้น (Strictly Scoped Path)
- ค้นหาและอ่านไฟล์ handoff (เช่น `handoff.md`, `handoff_task.md`) **เฉพาะที่อยู่ในโฟลเดอร์ของพาธที่ผู้ใช้ระบุโดยตรงเท่านั้น**
- **ห้ามอ่านไฟล์ handoff จาก Root directory หรือโฟลเดอร์อื่นที่ไม่ได้ระบุเด็ดขาด**
- อ่านรายละเอียดงานล่าสุด, สถานะปัจจุบัน, และสิ่งที่ต้องทำต่อ

---

## 2. เปิดใช้งาน Caveman Mode ทันที (Immediate Caveman Mode)
- **ประสานงานสกิล:** `caveman`
- ปรับสไตล์การสื่อสารให้เป็นโหมด **caveman (กระชับ/Terse)** ทันที
- พูดสั้น ตรงประเด็น ตัดคำฟุ่มเฟือยทั้งหมด แต่คงความถูกต้องทางเทคนิค 100%

---

## 3. เปิดเกราะความปลอดภัยสูงสุด (Activate Aegis Guardrails)
- **ประสานงานสกิล:** `aegis`
- บังคับใช้กฎ SAP SQL Server Read-Only 100%
- บังคับใช้กฎจำกัดขอบเขตโฟลเดอร์ (ห้ามรันคำสั่งใน Root Workspace)
- บังคับใช้กฎการสงวนรักษาโค้ดเดิม (Strict Code Preservation)

---

## 4. แนะนำชื่อเซสชัน (Suggest Session Title)
- ในบรรทัดแรกสุดของคำตอบ ให้แนะนำชื่อหัวข้อเซสชันอย่างเด่นชัดเพื่อให้คัดลอกได้ทันที:
  `📌 แนะนำตั้งชื่อเซสชันนี้เป็น: [Atlas] - [ชื่อโฟลเดอร์ย่อย]`

---

## 5. สรุปสถานะงานแบบกระชับ (Terse Status Summary)
- สรุปสถานะงานสั้นๆ ในรูปแบบ Caveman:
  - งานที่ผ่านมาทำอะไรไปแล้ว
  - สถานะปัจจุบันของระบบ
  - ขั้นตอนถัดไปที่ระบุไว้ใน `handoff.md`

---

## 6. หยุดรอรับคำสั่งทันที (CRITICAL: Wait for Orders)
- **กฎเหล็กสูงสุด:** เมื่ออ่านข้อมูลและสรุปสถานะเสร็จแล้ว **ห้ามลงมือแก้โค้ด รันคำสั่ง หรือทำอะไรต่อทั้งสิ้น**
- **ให้หยุดรอรับคำสั่งที่ชัดเจนจากผู้ใช้ก่อนเสมอ**
