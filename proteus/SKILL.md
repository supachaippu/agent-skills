# Proteus: Safe Code Modification & Regression-Free Refactoring

เมื่อต้องแก้ไขโค้ดเดิม, ปรับปรุงฟังก์ชันที่มีอยู่, ปรับโครงสร้างระบบ (Refactor), หรือพิมพ์ `/proteus`, "แก้โค้ดเดิม", "ปรับโครงสร้าง", "modify code":
ให้ปฏิบัติตามขั้นตอนเพื่อความปลอดภัยสูงสุด ป้องกันโค้ดพังหรือฟีเจอร์เดิมสูญหายดังนี้:

---

## กฎเหล็กสูงสุด: มาตรการล็อกขอบเขตการแก้ไขโค้ด (Strict Code Preservation)
- **ห้ามลบโค้ดเดิมโดยพลการ:** ห้ามลบ ปรับโครงสร้าง หรือทำความสะอาดโค้ด (Cleanup) ส่วนที่ทำงานถูกต้องอยู่แล้ว หากไม่ได้ถูกสั่งการให้แก้ไขโดยตรง
- **ห้ามตัด Feature เดิม:** โค้ดที่ทำงานได้อยู่แล้วต้องคงความสามารถเดิมไว้ครบถ้วน 100%
- **แจ้งเตือนและขออนุมัติล่วงหน้า:** หากจำเป็นต้องแตะต้องโมดูลที่เกี่ยวโยง ต้องแสดงแผนงานให้ผู้ใช้อนุมัติก่อนเสมอ

---

## ขั้นตอนที่ 1: ตรวจสอบและประเมินโค้ดเดิม (Code Review & Baseline)
- **ประสานงานสกิล:** `code-review`
- ศึกษาสถานะปัจจุบันของโค้ดที่จะแก้ไข ทำความเข้าใจ Call stack และ Data flow
- ระบุจุดเชื่อมโยง (Dependencies) และประเมินผลกระทบที่อาจเกิดขึ้น (Blast radius)

---

## ขั้นตอนที่ 2: ล็อกพฤติกรรมเดิมด้วยแบบทดสอบ (Lock Behavior via TDD)
- **ประสานงานสกิล:** `tdd`
- ก่อนลงมือแก้โค้ด ให้เขียน Test เพื่อยืนยันว่าพฤติกรรมเดิมที่ถูกต้องยังคงทำงานได้ (Regression safety net)
- ยืนยันว่าชุดทดสอบเดิมรันผ่านทั้งหมด

---

## ขั้นตอนที่ 3: ลงมือแก้ไขอย่างแม่นยำและจำกัดขอบเขต (Surgical Implementation)
- **ประสานงานสกิล:** `implement`
- ทำการแก้ไขเฉพาะจุดที่ได้รับมอบหมาย โดยแก้ไขให้น้อยที่สุดและตรงจุดที่สุด (Surgical patch)
- รักษา Coding conventions, รูปแบบตัวแปร, และคอมเมนต์เดิมไว้ทั้งหมด

---

## ขั้นตอนที่ 4: เสริมความลึกของสถาปัตยกรรม (Improve Architecture)
- **ประสานงานสกิล:** `improve-codebase-architecture`
- หากมีการ Refactor ตามคำสั่ง ให้ยึดหลัก Deep Modules:
  - ลดความซับซ้อนของ Public API
  - กักเก็บตรรกะภายในไว้ให้เป็นระเบียบ
  - ไม่เปิดเผย Internal state ออกสู่ภายนอกโดยไม่จำเป็น

---

## ขั้นตอนที่ 5: ตรวจสอบอิสระรอบด้านป้องกันผลข้างเคียง (External Scrutiny)
- **ประสานงานสกิล:** `scrutinize`
- จำลองมุมมองจากผู้ตรวจสอบภายนอก (Outsider perspective):
  - โค้ดที่แก้ทำงานตรงตามคำสั่งจริงหรือไม่?
  - มี Side effects หรือพฤติกรรมแฝงที่ไม่พึงประสงค์หรือไม่?
  - โค้ดส่วนอื่นยังคงทำงานได้สมบูรณ์โดยไม่มี Regression หรือไม่?
- รันชุดทดสอบทั้งหมดอีกครั้งเพื่อยืนยันความสมบูรณ์ 100%
