# Proteus: Safe Code Modification & Regression-Free Refactoring

เมื่อต้องแก้ไขโค้ดเดิม, ปรับปรุงฟังก์ชันที่มีอยู่, ปรับโครงสร้างระบบ (Refactor), หรือพิมพ์ `/proteus`, "แก้โค้ดเดิม", "ปรับโครงสร้าง", "modify code":
AI **ต้องแสดงกล่องติดตามสถานะ (Pipeline Tracker) ในคำตอบแรกเสมอ** และปฏิบัติตามลำดับขั้นตอนดังนี้:

ในทุกๆ ข้อความตอบกลับ AI **ต้องพิมพ์กล่องสถานะนี้ไว้บนสุดของคำตอบเสมอ**:

[3/5] TDD Behavior Lock: [⏸️/✅ เขียน Test ล็อกพฤติกรรมเดิมก่อนแตะต้องโค้ด]

## กฎเหล็กสูงสุด: มาตรการล็อกขอบเขตการแก้ไขโค้ด (Strict Code Preservation)
- **ห้ามลบโค้ดเดิมโดยพลการ:** ห้ามลบ ปรับโครงสร้าง หรือทำความสะอาดโค้ด (Cleanup) ส่วนที่ทำงานถูกต้องอยู่แล้ว หากไม่ได้ถูกสั่งการโดยตรง
- **ห้ามตัด Feature เดิม:** โค้ดที่ทำงานได้อยู่แล้วต้องคงความสามารถเดิมไว้ครบถ้วน 100%

---

## ขั้นตอนที่ 1: ตรวจสอบและประเมินผลกระทบ (Code Review & Blast Radius)
- **ประสานงานสกิล:** `code-review`
- ศึกษาสถานะปัจจุบันของโค้ด ทำความเข้าใจ Call stack และระบุจุดเชื่อมโยง (Dependencies)
- อัปเดตข้อ [1/5] เป็น ✅

---

## ขั้นตอนที่ 2: จุดเบรกที่ 1 — แสดงแผนการแก้ไขและรออนุมัติ (MANDATORY REFACTOR PLAN)
- 🛑 **คำสั่งเบรกแตก:**
  1. อัปเดตข้อ [2/5] ใน Tracker เป็น `🛑 หยุดรออนุมัติแผนการแก้ไข`
  2. **ห้ามลงมือแก้โค้ดหรือเขียนทับไฟล์ใดๆ ในรอบนี้เด็ดขาด**
  3. สรุป Implementation Plan: รายชื่อไฟล์ที่จะแก้, เหตุผล, และการยืนยันว่าจะไม่ลบ Feature เดิม
  4. **หยุดรอคำยืนยันอนุมัติจากผู้ใช้ก่อน จึงจะเริ่มลงมือแก้ไขจริงได้**

---

## ขั้นตอนที่ 3: ล็อกพฤติกรรมเดิมด้วยแบบทดสอบ (Lock Behavior via TDD)
- **ประสานงานสกิล:** `tdd`
- เมื่อได้รับอนุมัติ อัปเดตข้อ [2/5] เป็น ✅ และข้อ [3/5] เป็น ⏳
- รันหรือเขียน Test ยืนยันว่าพฤติกรรมเดิมที่ถูกต้องยังคงทำงานได้ (Regression safety net)
- อัปเดตข้อ [3/5] เป็น ✅

---

## ขั้นตอนที่ 4: ลงมือแก้ไขอย่างแม่นยำและจำกัดขอบเขต (Surgical Implementation)
- **ประสานงานสกิล:** `implement` และ `improve-codebase-architecture`
- ทำการแก้ไขเฉพาะจุดที่ได้รับอนุมัติอย่างแม่นยำ ยึดหลัก Deep Modules
- อัปเดตข้อ [4/5] เป็น ✅

---

## ขั้นตอนที่ 5: ตรวจสอบอิสระรอบด้านป้องกันผลข้างเคียง (External Scrutiny)
- **ประสานงานสกิล:** `scrutinize`
- จำลองมุมมองคนนอก ตรวจสอบว่าโค้ดทำงานตรงตามคำสั่ง ไร้ Side effects แฝง และรันเทสต์ผ่าน 100%
- อัปเดตข้อ [5/5] เป็น ✅
