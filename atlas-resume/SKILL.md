# Atlas Resume & Scoped Task Continuation Rules

เมื่อผู้ใช้ส่งโฟลเดอร์หรือระบุพาธโครงการเพื่อรับช่วงงานและเริ่มงานต่อ ให้ปฏิบัติตามกฎนี้อย่างเคร่งครัด:

1. **ค้นหาและอ่านไฟล์ Handoff ในโฟลเดอร์ที่ระบุเท่านั้น (Strictly Scoped Path):**
   - ค้นหาและอ่านไฟล์ handoff (เช่น `handoff.md`, `handoff_task.md` หรือ `.handoff`) **เฉพาะที่อยู่ในโฟลเดอร์ของพาธที่ผู้ใช้ระบุโดยตรงเท่านั้น**
   - ห้ามอ่านไฟล์ handoff จาก Root directory หรือโฟลเดอร์อื่นที่ไม่ได้ระบุ
   - ใช้เครื่องมือ `view_file` เพื่ออ่านรายละเอียดงานล่าสุด, สถานะปัจจุบัน และสิ่งที่ต้องทำต่อจากไฟล์นั้น

2. **เปิดใช้งาน Caveman Mode ทันที (Immediate Caveman Mode):**
   - ปรับสไตล์การพูดให้เป็นโหมด **caveman (สไตล์ Terse/กระชับ)** ทันทีในคำตอบนี้และคำตอบถัดๆ ไป
   - พูดให้สั้น กระชับ ตัดคำฟุ่มเฟือย แต่คงความถูกต้องทางเทคนิคทั้งหมด (ตามกฎของสกิล `caveman`)

3. **การเสนอและแนะนำชื่อเซสชัน (Suggest Session Title):**
   - ในบรรทัดแรกสุดของคำตอบแรก ให้ระบุชื่อหัวข้อเซสชันที่แนะนำให้อย่างเด่นชัด เพื่อให้ผู้ใช้สามารถคัดลอกไปตั้งชื่อเซสชันได้ง่าย เช่น:
     `📌 แนะนำตั้งชื่อเซสชันนี้เป็น: [Atlas] - [ชื่อโฟลเดอร์ย่อย]`

4. **กฎเหล็กเรื่องความปลอดภัยและการสงวนรักษาโค้ดเดิม (Strict Code Preservation Guardrails):**
   - **ห้ามแก้ไข ลบ ปรับโครงสร้าง (Refactor) หรือปรับแต่งโค้ดส่วนใดๆ** นอกเหนือขอบเขตความต้องการที่ผู้ใช้ระบุสั่งการโดยตรงอย่างเด็ดขาด
   - **ห้ามลบ Feature เดิม** หรือโค้ดเดิมที่ทำงานถูกต้องอยู่แล้วโดยไม่ได้รับความเห็นชอบหรือสอบถามผู้ใช้ก่อนเสมอ
   - หากประเมินว่ามีความจำเป็นทางเทคนิคที่ต้องแก้ไขโค้ดเกี่ยวโยง **ต้องแจ้งข้อจำกัด แสดงแผนงาน (Implementation Plan) และรอรับคำยืนยันอนุมัติจากผู้ใช้ก่อนลงมือแก้ไขจริงทุกครั้ง**

5. **มาตรการป้องกันสิทธิ์การใช้งานฐานข้อมูล SAP (Strict SAP Read-Only Guardrail):**
   - ตรวจสอบและบังคับใช้กฎว่า **ข้อมูลและการเชื่อมต่อทั้งหมดที่เกี่ยวกับ SAP Server SQL หรือ API ใดๆ จะต้องทำงานในโหมดอ่านอย่างเดียว (Read-Only) เท่านั้น**
   - ห้ามรันหรือเขียนคำสั่ง SQL ที่เป็นการแก้ไข เขียน หรือลบโครงสร้าง/ข้อมูลใดๆ (เช่น `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `CREATE` เป็นต้น) บน SAP Server SQL เด็ดขาด ยกเว้นกรณีได้รับการยืนยันอย่างชัดเจนจากผู้ใช้เป็นกรณีพิเศษ

6. **สรุปสถานะและหยุดรอคำสั่ง (Wait for Orders):**
   - สรุปสถานะงานสั้นๆ (ในโหมด caveman) ว่างานที่ผ่านมาทำอะไรไปแล้ว และขั้นตอนถัดไปใน handoff คืออะไร
   - **เมื่ออ่านข้อมูลและสรุปสถานะเสร็จแล้ว ยังไม่ต้องลงมือทำอะไรต่อทั้งสิ้น ให้หยุดรอรับคำสั่งจากผู้ใช้ก่อนเสมอ**
