# Hercules: Systematic Bug Hunting, Diagnosis & Remediation Pipeline

เมื่อระบบเกิดข้อผิดพลาด, มีบัค, โปรแกรมพัง, หรือผู้ใช้พิมพ์ `/hercules`, "แก้บัค", "debug", "หาบัค", "error":
ให้เข้าสู่วินัยการแก้บัคแบบเป็นระบบตามลำดับขั้นตอนดังนี้ ห้ามเดาสาเหตุหรือแก้ไขโค้ดแบบสุ่มสี่สุ่มห้าเด็ดขาด:

---

## ขั้นตอนที่ 1: ท่องและยึดมั่นคาถา 4 ข้อแห่งการดีบัก (Debug Mantra)
- **ประสานงานสกิล:** `debug-mantra`
- ทบทวนและนำคาถาทั้ง 4 ข้อมาปฏิบัติอย่างเคร่งครัด:
  1. **Reproduce (จำลองเหตุการณ์ให้ได้):** สร้างขั้นตอนที่ทำให้บัคเกิดขึ้นซ้ำได้แน่นอน 100%
  2. **Trace the fail path (แกะรอยเส้นทางล้มเหลว):** ไล่ Stack trace และ Execution flow จากจุดพังย้อนกลับไปหาต้นทาง
  3. **Falsify the hypothesis (พิสูจน์หักล้างสมมติฐาน):** ตั้งสมมติฐานแล้วทดสอบเพื่อหักล้าง อย่าปักใจเชื่อข้อสันนิษฐานแรก
  4. **Cross-reference every breadcrumb (เชื่อมโยงหลักฐานทุกชิ้น):** ตรวจสอบ Logs, ตัวแปร, สถานะระบบ, และเงื่อนไขขอบเขตทั้งหมด

---

## ขั้นตอนที่ 2: วินิจฉัยหาสาเหตุที่แท้จริง (Deep Diagnosis Loop)
- **ประสานงานสกิล:** `diagnosing-bugs`
- บันทึกพฤติกรรมจริง (Actual) เทียบกับพฤติกรรมที่ควรจะเป็น (Expected)
- ค้นหาจุดแตกหักที่แน่นอนในโค้ด (Root Cause) โดยไม่แตะต้องหรือแก้ไขโค้ดใดๆ ในระหว่างขั้นตอนการวินิจฉัย

---

## ขั้นตอนที่ 3: ล็อกบัคด้วยแบบทดสอบที่ล้มเหลว (Pin Bug via Failing Test)
- **ประสานงานสกิล:** `tdd`
- เขียน Unit Test หรือ Integration Test ที่จำลองเงื่อนไขที่ทำให้เกิดบัค
- รันแบบทดสอบและต้องเห็นสถานะ **RED (Fail)** ชัดเจน เพื่อพิสูจน์ว่าแบบทดสอบสามารถจับบัคนี้ได้จริง

---

## ขั้นตอนที่ 4: ผ่าตัดแก้ไขเฉพาะจุดอย่างแม่นยำ (Surgical Fix)
- ดำเนินการแก้ไขโค้ดที่เป็นต้นตอของบัคโดยใช้การแก้ไขที่เล็กและปลอดภัยที่สุด (Minimal surgical fix)
- **กฎเหล็ก:** ปฏิบัติตามมาตรการ Strict Code Preservation ห้ามลบ ปรับแต่ง หรือแตะต้องฟังก์ชันข้างเคียงที่ทำงานถูกต้องอยู่แล้วเด็ดขาด

---

## ขั้นตอนที่ 5: ยืนยันผลการแก้ไข (Verify Green)
- รันแบบทดสอบที่เขียนไว้ในขั้นตอนที่ 3 จนสถานะกลายเป็น **GREEN (Pass)**
- รัน Regression test ทั้งหมดในระบบเพื่อให้มั่นใจว่าไม่มีสิ่งใดพังเสียหายต่อเนื่อง

---

## ขั้นตอนที่ 6: จัดทำบันทึกวิเคราะห์สาเหตุเชิงวิศวกรรม (Post-Mortem / RCA)
- **ประสานงานสกิล:** `post-mortem`
- บันทึกรายงาน Root Cause Analysis (RCA) สรุป:
  - สาเหตุที่แท้จริง (Root Cause)
  - กลไกที่ทำให้เกิดความผิดพลาด (Failure Mechanism)
  - วิธีการแก้ไขและผลการตรวจสอบ (Fix & Validation)
  - ช่องว่างที่ทำให้หลุดรอดมาได้และแนวทางป้องกันในอนาคต

---

## ขั้นตอนที่ 7: ทบทวนกระบวนการทำงานเพื่อปรับปรุง (Retrospective)
- **ประสานงานสกิล:** `retro`
- สรุปบทเรียนสั้นๆ ว่าระบบหรือกระบวนการทำงานส่วนใดควรเพิ่มเกราะป้องกันเพื่อไม่ให้เกิดบัคประเภทนี้ซ้ำอีก
